# AnoTerm

[日本語](README.md) | [English](README.en.md) | [简体中文](README.zh.md) | **한국어**

Android용 SSH 클라이언트 겸 터미널 에뮬레이터. Kotlin + Jetpack Compose.

이 프로젝트가 존재하는 이유는 **전각 문자를 올바른 너비로 그리는 것**입니다. Android의
터미널 앱은 한중일 문자가 나오는 순간 커서 위치가 어긋나고, 거기서부터 화면이 무너집니다.
문자 너비 판정과 UTF-8 디코딩을 다른 것에 맡기지 않고 직접 구현한 이유가 그것입니다.

> **앱 화면의 언어는 아직 영어와 일본어뿐입니다.** 이 문서는 한국어지만 앱은 아직입니다.
> 터미널에 표시되는 내용은 접속한 서버가 보내는 것이므로 이 제한과 무관합니다.

## 기능

### 터미널로서

- **전각 문자와 결합 문자를 올바른 너비로 그린다** — `CharWidth.kt`가 East Asian Width를
  해석하고, `Utf8Decoder.kt`가 서로게이트 쌍과 잘린 바이트열을 처리합니다
- **터미널 에뮬레이션** — `TerminalEmulator.kt`: 대체 화면, 스크롤 영역, 마우스 보고, DECCKM 등
- **기록에서 찾기** — ⋮ 메뉴에서. 이 연결로 흘러간 글자를 찾습니다(셸의 히스토리도,
  파일의 내용도 아닙니다). 일치한 곳은 칠해지고, 화살표로 그 사이를 오갑니다
- **관성이 붙는 스크롤** — 세게 튕기면 계속 흐릅니다. 거슬러 올라가 있는 동안에는 아래에
  「몇 줄 앞인지」가 나오고, 누르면 최신으로 돌아옵니다
- **화면 높이가 바뀌어도 읽고 있던 줄이 움직이지 않는다** — 위로 넘친 줄은 버리지 않고
  스크롤백으로 보내고, 넓어지면 도로 끌어옵니다. 기록을 읽는 동안 맨 윗줄은 전혀 움직이지 않습니다

### 연결과 인증

- **접속 대상 관리** — 호스트·포트·사용자 이름을 Room에 저장
- **인증** — 비밀번호와 개인키 양쪽. 패스프레이즈가 걸린 키도 지원
- **공개키 등록(`ssh-copy-id` 상당)** — 비밀번호로 이미 연결된 세션을 이용해 공개키를
  상대의 `~/.ssh/authorized_keys`에 덧붙입니다. Android만으로 키 인증으로 옮겨갈 수 있습니다.
  중복 등록하지 않고, 기존 키도 건드리지 않습니다
- **호스트 키 검증(TOFU)** — 첫 키를 기록하고 **바뀌면 연결을 거부합니다**. 첫 연결 때
  기록한 지문을 보여주므로 서버의 `ssh-keygen -lf`와 대조할 수 있습니다
- **자격 증명 암호화 저장** — Android Keystore의 키로 보호되는 `EncryptedFile`
- **앱 잠금** — 생체 인증(선택)
- **백그라운드 연결** — 포그라운드 서비스가 화면이 꺼져 있어도 세션을 유지합니다

### tmux

- **자동 attach** — 호스트 설정에 세션 이름을 넣어두면 연결 후 `tmux new -A -s <이름>`을
  보냅니다. 끊겨도 하던 일이 남습니다
- **창 목록(≡)** — 왼쪽에서 나오는 서랍에, 열려 있는 모든 연결의 모든 창이
  연결 → 세션 → 창의 3단으로 늘어섭니다. **어느 것이든 한 번에 갈 수 있습니다.**
  출력이 있었던 창에는 표시가 붙고, 안에서 무엇이 도는지도 나옵니다
- **전환 바** — 지금 있는 연결의 tmux 창이 늘어섭니다. 한 번 누르면 그리로 갑니다.
  ⋮ 메뉴에서 숨길 수 있습니다
- **prefix 키를 전혀 보내지 않는다** — tmux 조작은 전부 `tmux` 명령 실행입니다. 앞쪽 앱이
  Ctrl-B를 쥐고 있어도 듣고, `.tmux.conf`에서 prefix를 바꿔놨어도 상관없습니다
- 목록은 터미널에 쳐넣는 것이 아니라 별도의 SSH 세션으로 읽으므로, 작업 중인 화면에
  출력이 섞이지 않습니다

### 손안에서 확인하기

- **이미지 열기** — 터미널에 나온 경로에 밑줄이 붙고, 누르면 그 이미지가 나옵니다.
  Claude Code나 Codex가 그림이나 스크린샷을 써도 터미널에 남는 건 경로뿐이라,
  휴대폰에서는 거기서 끝이었습니다. 핀치로 확대할 수 있습니다
- **문서 열기** — `.md` `.kt` `.json` `.diff` 등 50여 종. 줄 번호가 붙고 줄바꿈은 하지 않습니다
  (코드를 접으면 들여쓰기가 무너져 구조가 보이지 않습니다)
- **페이지를 터미널 옆에서 보기** — `http://` URL을 누르면 터미널 옆에 브라우저가 열립니다.
  **통신은 이 SSH 연결 안을 지나므로**, `localhost`에만 열어둔 개발 서버도 밖에 드러내지 않고
  볼 수 있습니다. 대기는 휴대폰 안의 127.0.0.1에만 합니다. 위아래로도 좌우로도 나눌 수 있고,
  사이의 칸막이로 비율을 바꿉니다. 휴대폰의 브라우저로 넘겨 전체 화면으로 볼 수도 있습니다
- 읽어오는 일은 전부 **작업 중인 셸과는 별개의 SSH 세션**을 쓰므로, 명령줄에 군더더기가
  섞이지 않습니다. 상대 경로는 tmux 페인의 현재 위치에서 찾습니다

### 좁은 화면을 위한 설계

- **터미널만 남기는 전체 화면** — 위쪽 바도, tmux 줄도, 상태 표시줄도 사라집니다.
  두 손가락 더블 탭으로 드나들고, 한 번 탭하면 위쪽 바가 잠깐 내려옵니다(탭과 축소 버튼).
  뒤로 가기로도 빠져나옵니다
- **탭은 위쪽 바 안에** — 탭 이름이 곧 「지금 어느 연결에 있는가」라서 바의 제목과 역할이
  겹칩니다. 한 줄로 접었습니다
- **떠 있는 응답 패드** — 키보드를 닫고 있는 동안 1/2/3과 Esc, 키보드 키가 터미널 위에
  떠 있습니다. 확인 프롬프트에 답하려고 입력기를 열어 정작 확인할 내용을 가릴 필요가 없습니다.
  가운데 손잡이를 길게 누르면 방향키와 엔터로 바뀝니다(목록을 오르내릴 때). 원하는 곳으로
  옮길 수 있습니다
- **보조 키는 치는 동안만** — Esc·방향키·Ctrl·Shift+Tab은 키보드와 함께 나왔다 사라집니다.
  읽는 동안까지 두기에는 화면이 좁습니다
- **내측 카메라를 피한다** — 접는 화면을 펴면 카메라가 화면 안에 있습니다. 시스템이 알려주는
  가려진 영역만큼 자동으로 비킵니다. 모자라면 설정에서 왼쪽 여백을 더 줄 수 있습니다
- **닿은 곳으로 커서가 간다** — 상대가 마우스 보고를 요구하는 동안(Claude Code, vim,
  mouse를 켠 tmux)

### 그 밖에

- **제스처** — 아래 1/4 탭으로 키보드(떠 있을 때는 위쪽을 탭하면 숨김), 스와이프로 스크롤(세게 튕기면 계속 흐릅니다),
  더블 탭으로 Tab 보내기(두 손가락이면 전체 화면 드나들기), 길게 눌러 끌면 범위 선택과 복사, 핀치로 글자 크기.
  밑줄이 붙은 경로와 URL은 탭하면 열립니다. 전부 도움말에 적혀 있습니다
- **명령 기록**, **메모**, **사용자 단축키**
- **표시 설정** — 글자 크기(핀치로 바꾸면 그대로 저장됩니다), 줄 간격, 배색

## 화면 언어

영어와 일본어. 기본값은 기기 설정을 따르고, 설정에서 바꿀 수 있습니다(앱을 다시 시작할
필요는 없습니다).

문구는 전부 `strings.xml`에 있고 Kotlin에 직접 쓴 문자열은 남기지 않습니다.
`tools/check-strings.py`가 CI에서 돌며, 중복된 키·한쪽 언어에만 있는 키·서식 인자가 맞지 않는
키·아무도 참조하지 않는 키를 걸러냅니다.

터미널에 나오는 내용은 접속한 상대가 보내는 것이라 이 설정의 영향을 받지 않습니다.

## 동작 조건

- Android 7.0 (API 24) 이상
- JetBrains Mono를 함께 담고 있어 기기의 글꼴 설정에 좌우되지 않습니다

## 설치

### APK 넣기(권장)

[Releases](https://github.com/mirute02/anoterm/releases)에서 Android 기기의 브라우저로
내려받아, 알림이나 파일 앱에서 누릅니다. PC도 adb도 필요 없습니다.

처음에는 「출처를 알 수 없는 앱」 허용을 묻습니다. Android 8.0부터는 앱 단위 허용이므로,
브라우저나 파일 앱에 한 번 허용하면 됩니다.

Play 스토어를 거치지 않으므로 Play Protect가 확인 화면을 띄울 수 있습니다. 자체 서명이며,
인증서는 여기에 적어 둡니다(릴리스마다 적겠다고 약속하면 빠뜨린 판에서 거짓말이 됩니다.
한 곳에 두고 바꾸지 않는 편이 확인하기 쉽습니다):

```
CN=AnoTerm, OU=AnoTerm, O=AnoTerm, C=JP
SHA-256: 7e1677c2e1094ca36b9584990beabb2fb1668b327417ead3b0993ec1b99bbbdb
```

손에 있는 APK와 맞춰보려면 `apksigner verify --print-certs <apk>`.
**이 지문은 바뀌지 않습니다.** 키가 바뀐 앱은 Android가 다른 앱으로 취급해 덮어쓸 수 없으므로,
지문이 다른 APK는 이 프로젝트의 것이 아닙니다.

### 직접 빌드하기

```bash
git clone https://github.com/mirute02/anoterm.git
cd anoterm
./gradlew assembleDebug
```

`app/build/outputs/apk/debug/app-debug.apk`가 만들어집니다.
서명 키가 없는 환경에서는 release 빌드가 서명 없이 나오므로 배포에는 쓸 수 없습니다.

## 빌드

```bash
./gradlew assembleDebug
```

`namespace`와 `applicationId`는 `app.anoterm`(debug 빌드는 `.debug` 접미사).

### 테스트

```bash
./gradlew test
```

단위 테스트 124개가 푸시마다 CI에서 돕니다. 터미널 에뮬레이션, 문자 너비 계산, UTF-8 디코딩,
입력기의 미확정 문자열, 크기 변경 때 줄이 사라지지 않는 것, 화면에서 경로와 URL을 잘라내는 것
(줄바꿈을 넘는 이어붙이기, 셸 인용), tmux 출력 해석, 포트 전달 대상 구성이 대상입니다.

기기를 꽂지 않은 채로 개발하고 있어 **눈으로 봐야 아는 부분은 테스트로 덮지 못했습니다**.
논리로 떼어낼 수 있는 것은 떼어내 테스트에 싣고, 그리기와 입력의 감촉은 release를 실기에
넣어 확인합니다.

### Release 빌드

서명 키는 저장소에 넣지 않고 `gradle.properties`(또는 CI의 Secrets)에 둡니다:

```properties
ANOTERM_STORE_FILE=/absolute/path/to/release.jks
ANOTERM_STORE_PASSWORD=...
ANOTERM_KEY_ALIAS=...
ANOTERM_KEY_PASSWORD=...
```

인증서의 DN은 APK를 손에 넣은 누구나 읽을 수 있으므로, 실명이 아니라 프로젝트 이름을 넣습니다.
한 번 배포한 키는 바꿀 수 없습니다. 자세한 내용은
[docs/RELEASE_SIGNING.md](docs/RELEASE_SIGNING.md).

## 보안

SSH 클라이언트는 상대의 자격 증명을 맡고, 그 열쇠로 임의의 명령을 실행할 수 있는 단말이 됩니다.
[docs/security.md](docs/security.md)에 자격 증명을 암호화해 저장한다는 것,
호스트 키가 바뀌면 **경고하고 계속하는 것이 아니라 거부한다**는 것, 그리고 기기 잠금이 뚫리면
자격 증명이 꺼내질 수 있다는 한계를 적어 두었습니다.

개인정보 처리방침은 [docs/PRIVACY_POLICY.md](docs/PRIVACY_POLICY.md).
