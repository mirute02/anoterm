# セキュリティ — 何が守られていて、何が守られていないか

SSH クライアントは、接続先のパスワードや秘密鍵を預かり、その鍵で任意のコマンドを
実行できる端末になる。守れている範囲と、仕組み上どうにもならない範囲を分けて書く。

## 1. 資格情報の保護

- **暗号化して保存する。** パスワードと秘密鍵の本体は `filesDir/secrets/` に
  `<secretId>.bin` として置き、Android Keystore の鍵（`MasterKey`,
  `AES256_GCM`）で `EncryptedFile`（`AES256_GCM_HKDF_4KB`）により暗号化する。
  平文で書き出す経路はない
- **復号したバイト列を外に出さない。** 復号は `SecretStore` のメソッド内で完結し、
  呼び出し元にバイト列を渡さない
- **バックアップと端末間移行の両方から除外する。** `backup_rules.xml` と
  `data_extraction_rules.xml` の `cloud-backup` / `device-transfer` の3系統すべてで
  `secrets/`・`anoterm.db`・`anoterm_prefs.xml` を除外している。
  `allowBackup=false` だけでは一部メーカー端末の移行を止められないため
- **ログに出さない。** パスワード・パスフレーズ・秘密鍵をログに渡している箇所はない
- **アプリロック（生体認証）は任意。** 有効にすると起動時に認証を要求する。
  ただしこれは UI の入口を塞ぐだけで、**Keystore の鍵自体にユーザー認証を
  要求していない**。後述の限界を参照

## 2. 接続先の検証（TOFU）

`HostKeyVerifier` は Trust On First Use。

| 状況 | 動作 |
|---|---|
| 初回接続 | ホスト鍵の SHA-256 フィンガープリントを Room に記録して接続する |
| 記録と一致 | 接続する |
| **記録と不一致** | **接続を拒否する**（警告してフォールバックしない） |

鍵が変わったときに黙って受け入れないことが、この実装の要点である。中間者攻撃は
まさにそこで検知される。初回接続時は検証の対象がないので、**最初の接続だけは
信頼に基づく**。重要なホストは、初回接続後にフィンガープリントを別経路
（サーバー側で `ssh-keygen -lf`）で突き合わせること。

`findExistingAlgorithms` は空を返す。sshj に既知の鍵種別を伝えないため、
サーバーが提示する鍵種別がこちらの記録と異なる場合、その種別では初回扱いになる。

## 3. 通信

- SSH（sshj 0.40.0）による暗号化通信のみ。生 socket を直接扱う
- `network_security_config.xml` で **cleartext を全面禁止**し、system CA のみを
  信頼する。SSH は CA を使わないが、将来 HTTP 呼び出しが混入した場合の防波堤として
  明示している
- 権限は `INTERNET` / `ACCESS_NETWORK_STATE` / `USE_BIOMETRIC` / `VIBRATE` /
  `POST_NOTIFICATIONS` / `FOREGROUND_SERVICE(_SPECIAL_USE)` のみ。
  ストレージ・連絡先・位置情報は要求しない

## 4. 他アプリからの操作

- `MainActivity` のみ `exported="true"`（ランチャー起動のため）
- `SshForegroundService` は `exported="false"`
- 外部から接続先やコマンドを指定できる Intent フィルタは公開していない

## 5. 塞げていないもの（仕組み上の限界）

- **端末のロックを破られた場合、資格情報は取り出されうる。** Keystore の鍵に
  ユーザー認証を要求していないため、アプリのプロセスとして動けば復号できる。
  アプリロックを有効にしていても、それは UI の入口であってデータの鍵ではない
- **root 化された端末では保護は成立しない。** `filesDir` を読める主体は
  Keystore にも到達しうる
- **初回接続は検証できない。** TOFU の構造上、最初の鍵を信じるほかない
- **接続先サーバーの安全性はこのアプリの範囲外。** SSH は認証された相手との
  暗号化通信を提供するだけで、その相手が誠実かどうかは保証しない
- **画面の内容は保護していない。** スクリーンショット禁止（`FLAG_SECURE`）は
  設定していない。ターミナルの表示内容は他アプリのオーバーレイや録画から
  見えうる
- **sshj と Bouncy Castle の脆弱性はこのアプリの範囲外。** 更新に追随する以上の
  ことはできない

## 6. 意図的にやっていないこと

- **ホスト鍵の変更を「警告して続行」にしない。** そこで止まらなければ TOFU に
  意味がない。鍵を張り替えた場合は、既知ホストの記録を明示的に削除する
- **資格情報をクラウドに同期しない。** 同期は端末間移行の利便性と引き換えに、
  鍵の置き場所を一つ増やす
- **パスワードを自動入力・自動再送しない**
- **`FLAG_SECURE` を既定にしない。** ターミナルの内容をスクリーンショットに
  残せないと、作業ログを取る用途で不便になる。必要なら Android の
  「アプリ固定」やプロファイル分離を使うほうが目的に合う
